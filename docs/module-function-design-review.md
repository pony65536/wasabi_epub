# 各模块功能设计评审

日期：2026-10-03。依据当前工作区的 CLI、各格式流程、内容增强模块与 prompt。此次新增评审文档，未修改业务实现，也未运行真实翻译、视频封装或 PDF 渲染。

前几轮回归检查解决了内容保真、缓存与续跑等实现问题。本轮检查功能目标、默认策略和用户控制。下列建议属于产品与功能设计取舍；涉及模型质量、费用和阅读效果的收益尚需样本比较。

## 总体判断

现有模块大体都有用途，可以保留。主要问题是：多个模块同时决定译法、风格、内容取舍和执行顺序，却缺少统一的策略配置、证据优先级和质量报告。应先整理这些决定权，再扩展增强功能。

建议优先处理：

1. 让用户控制内容范围、注释、文风和处理模式；保真与覆盖审计始终启用。
2. 统一术语与人物信息的来源、优先级和修订方式。
3. 把翻译完成、格式验收与语义质量分别报告。
4. 为字幕补相邻语境与可读性验收，为 PDF 明确保留原文的覆盖报告。
5. 默认保留输入，成功任务的审阅材料采用独立保留策略。

## 模块清单

| 模块 | 当前功能取舍的问题 | 建议 |
|---|---|---|
| CLI / config / environment | 用户只能控制语言、范围、并发和 debug，难以分别控制文风、加注、审校与结构修复；增强阶段还可能使用不同 provider | 增加有限的处理方案及少量关键覆盖选项；启动前显示输入范围、会用到的阶段和 provider；提前校验所需能力 |
| core 编排 | EPUB 规划、Director、术语、标题处理等按固定流程执行；章节选择在 Director 之后；短任务也可能承担全书规划与抽样 | 先做本地结构分析和范围解析，再根据任务启用增强阶段；单章翻译允许有预算的全书背景抽样 |
| agent / chapterRoles | Index、Bibliography 默认不可进入翻译选择；Introduction、Prologue、Appendix 等统一延后，不适合所有书 | 角色分类与是否翻译、翻译顺序分开；默认尊重阅读顺序，正文优先作为可选策略；支持包含索引/参考材料 |
| translator / batchQueue | 节点与批次保证执行粒度，但不天然等于语义单元；固定四章窗口同时处理速度与上下文一致性 | 保留稳定节点映射；提供相邻段落只读语境；按处理方案决定章节并发，并固定记忆提交顺序 |
| content-classifier / coverage | 字母数量、公式样式等规则适合保护结构，却不能单独判断短标签、诗句、混排术语是否需要翻译；没有覆盖缺口的自动补选流程 | 每个单元记录 translate/preserve/review 及理由；人工保留项优先；发现缺口后提供定向补译，完成条件继续严格 |
| inlineSlots / structureGuard | 保留标签是合理的；但链接、代码、强调、公式的文本可修改范围不同 | 对对象分别约定属性保护、文本翻译、允许重排和嵌套规则；结构保护不能代替语义保护 |
| Director | 从少量样本推断的角色、人称和文风，在 prompt 中被作为严格全书约束；前言中的作者说明还可能被排除出抽样 | 把抽样结果作为有证据和置信度的建议；允许 unknown 和更正；作者/译者的明示要求优先；技术书按需关闭人物与世界观分析 |
| glossary | 词频候选和模型筛选适合启动词表，但高频不等于必须统一；与 Book Bible、动态记忆可能给出不同译法 | 允许导入/导出术语表；统一词条记录来源、语境和审批状态；按义项区分同形词；人工确认优先于自动提议 |
| memory | 人物与术语采用首次写入；人物稳定属性与随章节变化的信息缺少区分，错误初值难修正 | 稳定身份与章节状态分开；新增信息可修订且保留来源、历史；按确定顺序合并；旧章节修正后标出需复查的相关译文 |
| retriever | 当前主要按词表关键词检索译文，帮助统一术语，但不足以解决代词、省略和跨段指代；缓存章节可先全部进入索引 | 相邻原文语境优先，再检索实体证据和双语片段；传当前章节/段落位置；区分前文证据与全书背景，不把任意命中称作前文 |
| Critic | 主要以字符长度比和 ws-note 触发；同时承担完整性检查与润色；hasSevereIssue 没有独立报告出口 | 先做确定性数字、对象与覆盖检查；语义审校返回问题和建议，按策略应用；依据语言与体裁设门控和调用预算 |
| headings | 标题标准化目标合理，但使用整段模型输出调整编号、标点、空白，权限范围大于需要 | 拆分编号、前缀和标题正文，常见规则本地执行；特殊格式可由模型提议，实际修改限制在允许字段 |

| epubDoctor / linkRewriter / tocSync / epubSaver | 自动结构修复会改变章节粒度及选择编号；TOC 文案同步也会改变作者原有的简写或层级文案 | 本地输出修复摘要和章节映射；修复可关闭；把链接修复与目录标签重写分开，目录标签可保留原设计；最终包独立验收 |
| PDF 提取 / 保护 / 渲染 / 验收 | 原版式、可读译文和全文覆盖会互相制约；保留某些图表文字能保护图形，但读者可能仍无法读懂关键标签 | 保留当前论文能力边界；输出各页 translated/preserved/review 的范围与原因；复杂页可附阅读版 HTML 或双语文本；不要把协议完成视作版式与语义已达标 |
| SRT | 时间和 cue 映射保护合理，但 prompt 要求极短 cue 独立翻译，容易丢指代或半句语境；没有显式阅读速度、行长验收 | 输入邻近 cue 作为只读上下文，仍只写当前 cue；按目标语言检查字符数/秒、行数和断行；超限优先精简或报告，重定时作为独立选项 |

## 重点依据与影响

### 1. 内容取舍与执行顺序应由策略决定

`src/content/chapterRoles.js` 将 index/bibliography 放入 EXCLUDED_ROLES，并将 introduction/prologue/appendix 等归为 front。`src/core.js` 在构建章节选择列表时先排除 EXCLUDED_ROLES，再按角色分正文和前置材料执行。

因此，用户不能简单通过现有章节选择器纳入参考材料。技术书的 Introduction 可能定义正文术语，小说的 Prologue 可能提供叙事背景，延后翻译有明确取舍。正文优先可保留为方案，但角色不应同时决定可选择性与执行顺序。

### 2. 统一术语信息的最终决定权

`src/core.js` 将 Director 词表与初始 glossary 合并，正文阶段结束再合并动态 glossary；`formatBookBibleForPrompt` 还会单独输出 Book Bible 的术语。不同来源的覆盖次序和 prompt 中的约束没有统一的解释出口。

推荐优先级：人工确认词条 > 本项目批准的词条 > 当前上下文明示证据 > 未批准的模型建议。上下文义项应分开，不能仅按一个字符串永久固定译法。Director 负责风格建议，Glossary 负责已确认术语，Memory 负责新增证据与修订提议，Retriever 负责取证。

### 3. 语义质量不能用执行完成替代

EPUB/HTML/SRT 的 JobResult 目前会根据 translationStatus 给出 ok 或 partial 的 validationStatus。现有覆盖、结构和格式验收有实际价值，但它们不能证明没有错译、数字语义错误、术语冲突或字幕过快。

建议分别报告执行完成度、格式验收、语义审校状态与阅读质量。未经审校应显示未审校，而非暗示语义质量已经通过。Critic 返回的问题清单需要进入报告，而不只是产生一个非空 improved 字符串。

### 4. 自动加注的规则需要统一

`prompts/epub_translation_prompt.txt` 的第 5 条禁止 translator notes，第 12 条又允许 ws-note 文化脚注。Critic 的注释必要性判断也固定引用 Chinese readers，与多目标语言能力不一致。

应明确加注是否启用，以及允许加什么。若开启，只允许指定的 ws-note 通道，不允许正文夹带流程说明；文化必要性按目标读者判断。注释为生成内容，需要在审阅报告中单列。

### 5. 字幕需要语境与阅读约束

`prompts/subtitle_translation_prompt.txt` 要求极短 cue 独立翻译、不得借用相邻 cue 的措辞。单独输出每个 cue 是合理的结构要求，但输入语境可以包括前后 cue。两者应分别定义。

例如跨两个 cue 的半句话、he/she/it 或一句短回应，缺少相邻语境时模型容易误判。可读性应结合 cue 时长和目标语言测量；行长、行数与阅读速度先作为报告和精简依据，避免未经用户选择就改动时间轴。

### 6. 审阅与归档属于正常使用流程

四种 Job 写出后都会调用 moveFileIfNeeded 将输入放入 input；完整成功且符合清理条件时删除运行缓存和日志。这适合个人批处理习惯，但通用 CLI 使用者通常预期源文件留在原位置，且输出后仍可能修订术语或个别章节。

建议默认保留输入，显式开启归档；审阅资料与调试资料分别保留。质量报告至少包含范围、未翻项、保留原因、术语冲突、模型使用、调用量和验收状态。

## 推荐修改顺序

1. 增加统一任务策略：范围、顺序、注释、风格增强、标题处理、审校、归档与审阅资料保留。策略需参与任务身份，避免切换策略复用旧结果。
2. 统一术语库与实体证据，支持人工导入、确认和修订，明确冲突优先级。
3. 提供质量报告与定向重译；分别表示执行、格式和语义验收。
4. 字幕增加相邻语境与阅读约束；视频增加轨道选择。
5. 用小说、技术书、短 HTML、论文与连续字幕各一个小样本比较增强功能收益，再决定默认启用哪些能力。

不需要为这些目标更换队列、引入向量数据库或重写所有格式后端。现有保真、续跑和验收模块继续作为基础能力使用。
