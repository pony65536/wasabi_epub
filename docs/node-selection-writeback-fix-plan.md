# 节点选择、写回与缓存恢复修复计划

> 状态：步骤 1–5 已实施（见文末实施状态），步骤 6 的真实样本结构验收待跑。
> 范围：父子节点去重、实际写回状态、嵌套内容保护、缓存迁移与离线回归。
> 保留现有格式流程、提示词、模型路由和内容分类政策；不调用付费 API，不直接删除用户缓存。

## 1. 问题与已复现证据

当前改动解决了普通 `li > p` 的重复发送，但“直接文本为空”和“目标已经消失”都不足以证明内容已被正确处理。现有九组测试通过，以下反例仍然成立。

| 反例 | 当前实际结果 | 修复后要求 |
|---|---|---|
| `li > strong(引言) + p(正文)` | 只发送 p；strong 引言漏选，章节 partial | 引言与正文均进入唯一翻译单元，不产生父子重复任务 |
| 请求期间仅移除目标的 `data-t-id`，没有祖先覆盖 | 原文未替换，却返回 complete、translatedNodes=1 | 写回失败被独立记录，章节不得 complete |
| 外层 li 有直接文本、包含内层 ul/li；模型只返回外层译文 | 内层列表被删除，仍返回 complete | 列表结构或后代正文消失必须被拒绝 |
| 当前“祖先覆盖”测试的父响应不含子内容 | 测试通过，子内容已经丢失 | 检查内容和结构保留；不能只检查父节点写回成功 |

另外，`resumeFailedOnly` 直接收集缓存中的失败标记，绕过新选点逻辑；旧缓存可能继续携带父子重叠任务。已验证的 complete 缓存也不会仅因“没有失败标记”而自动重翻。

## 2. 必须成立的契约

1. 同一章节中的待发翻译单元彼此不包含；这个约束同时适用于首次翻译、结构回退和缓存续翻。
2. 应翻的源文本单元必须有唯一的处理归属；归属按源 DOM 节点位置建立，不用文本子串判断。
3. 容器是否交给子节点处理，依据“后代计划之外是否仍有应翻文本”，不是仅检查 DOM 直接文本。
4. `written` 只表示通过校验的结果已写入预期目标；收到响应、目标标记消失、队列 finish 都不能单独证明 written。
5. 未知目标缺失是结构异常，不是正常的祖先覆盖。没有成功证据不能跳过并计入完成。
6. 选择容器时，其原本包含的后代正文结构不能因写回而整体消失。
7. complete 必须同时满足：所有计划翻译单元确实 written、无未解决写回失败、无覆盖率缺口、结构校验通过。

不新增“祖先响应优先，所以子任务可以随意丢弃”的规则。正常新任务已经不允许父子重叠，原则上不会产生这种竞争。

## 3. 修改一：生成不重叠的节点计划

主要文件：`src/translation/translator.js`。

### 3.1 将候选发现与最终选中分开

当前显式候选仍使用 `p/li/h1…h6/caption/title`，沿用现有分类与保留原因。先生成候选关系和临时子计划，确定最终计划后才写 `data-t-id`、审计标记并分批，避免被撤销的子计划留下标记。

对每个候选容器：

1. 找出其最近的候选后代；中间允许有 div、span 等包装元素。
2. 递归计算后代的翻译/明确保留计划。
3. 在副本中移除这些后代计划已经接管的子树，检查剩余可见文本。保留剩余 strong、em、a、span 等行内包装中的文字；排除既有黑名单内容。
4. 用现有内容分类语义判断剩余文字是否应翻，不能仅使用 `trim()` 是否为空，也不能新增固定长度阈值替代分类。
5. 若容器可翻且仍有剩余应翻文字，选择整个容器，撤销它内部的子翻译任务；这些源文本改为归属于容器任务。
6. 若没有剩余应翻文字，并且后代计划足以接管内容，只使用后代计划。
7. 若没有可接管的后代，则按现有规则处理容器，不能因存在 CSS 候选标签就直接跳过。

容器含有明确保留的公式、图片等内容时，继续执行现有保留与保护规则；选中容器不授予模型删除或改写这些内容的权限。

### 3.2 示例

| 源结构 | 最终选择 |
|---|---|
| `<li><p>正文</p></li>` | p |
| `<li><strong>引言</strong><p>正文</p></li>` | li；strong 和 p 的文本都归属这个任务 |
| `<li>引言<ul><li>子项</li></ul></li>` | 外层 li；不再为内层 li 建任务 |
| `<li><ul><li>子项</li></ul></li>` | 内层 li |
| `<li><p>A</p><p>B</p></li>` | 两个互不包含的 p |
| 只有空白、数字或原有明确保留内容的容器 | 按既有分类保留或交给子计划，不随意扩大翻译范围 |

### 3.3 所有入口统一校验

增加内部计划校验函数，检查：

- 单元 ID 唯一、目标 DOM 身份唯一；
- 任意两个翻译目标不存在祖先/后代关系；
- 应翻源文本没有遗漏归属或重复归属；
- 所有目标仍在当前章节 DOM 中。

显式路径和结构回退生成的最终计划都必须经过校验。续翻旧缓存发现重叠标记时，不使用“祖先赢”修补；将该章标记为需要从原文重建，再执行同一套选点规则。

## 4. 修改二：用明确写回结果取代标记推算

主要文件：`src/translation/batchQueue.js`、`src/translation/translator.js`、`src/models/errors.js`。

### 4.1 章节内状态记录

为最终计划建立章节级记录，例如：

```js
{
  id,
  sourceDigest,
  targetRef,       // 仅运行时保留 DOM 引用，不序列化到缓存
  state,           // pending | written | failed
  outputDigest,
  failureCode,
  retryable
}
```

状态记录必须归属于章节/本次执行。不同章节都可能存在 `node_0`，不得在共享队列中只按这个 ID 存全局状态。

失败之后成功写回可以转为 written；非重试结构失败不得被章节恢复轮次重新请求。重复成功通知不重复计数。

### 4.2 写回流程

1. 请求前检查该任务仍有效；已确认 written 的重复任务不再发送 API 请求。
2. 完成响应解析、slot 和受保护结构校验，再进行写回检查。
3. 目标选择器必须命中恰好一个元素，并与计划保存的目标身份一致；同时确认它仍属于该章节。
4. 写回前检查目标源内容未被其他任务意外改写。内部审计标记按同一种规则规范化，避免把自身添加的标记误当成源内容变化。
5. 在同步提交段中写入合法节点的结果，移除相应失败标记，随后记录 written 和输出摘要。提交过程中不得等待其他模型请求。
6. 目标缺失、重复或身份不一致的节点记为结构失败；同批其他合法节点可以正常提交，但不能把整批都回调为翻译成功。
7. 若写入操作异常，恢复该节点提交前的内容和标记，并记录失败；不能留下“已移除标记、未记 written”的半完成状态。

目标缺失时，删除目前的无条件 `WARN + continue` 成功处理。仅当同一节点已有 written 记录、当前输出仍能与该记录核对一致，才能认定重复提交并幂等跳过。没有这个证据即失败；第一版无需实现 superseded 状态。

### 4.3 批次结果和进度

队列需要提供逐节点结果，例如：

```js
{
  writtenNodeIds,
  alreadyWrittenNodeIds,
  failedNodes: [{ id, code, retryable }]
}
```

`dispatchBatches` 读取这些结果，而不是仅凭 better-queue 的 finish 事件返回 `{ok:true}`。可使用 `cb(null, result)` 返回“任务已处理”的结果，但必须由调用方区分全部写回、部分写回和全部失败。

- 成功回调仅对应本次真实写回的节点；失败回调对应失败节点。
- 字幕进度按唯一 written 节点累计，重试或重复通知不增加完成数。
- `translatedNodes` 从状态记录计算，删除 `totalNodes - DOM 中剩余标记数` 作为完成证明的逻辑。
- DOM 标记继续用于定位和续翻，但不再作为唯一状态来源。

### 4.4 结构错误与重试

使用明确错误码，避免只根据字符串猜测原因：

| 错误码 | 类别 | 本次执行处理 |
|---|---|---|
| `TARGET_MISSING` | structure | 不重新请求该节点；记录失败，标记该章需从原文重建 |
| `TARGET_AMBIGUOUS` | structure | 同上 |
| `TARGET_CHANGED` | structure | 同上 |
| `OVERLAPPING_TARGETS` | structure | 请求前阻止发送；修复计划或重建该章 |
| 现有网络/截断/格式错误 | 沿用既有分类 | 继续执行网关有界重试与业务层修复/拆批 |

不可重试的状态必须传到章节重试、单节点回退和 `processHtmlBatch` 等调用方；只在 batchQueue 内快速失败，不能保证上层不会再次发送。

## 5. 修改三：保护容器内的正文结构

主要文件：`src/translation/structureGuard.js`；复用现有 slot 机制。

当前保护主要针对行内标签和带特定属性的元素。无属性的 ul/ol/li 等结构可被模型删除，因此选择整个容器后还需要补充局部正文结构保护。

- 对发送片段中存在的列表和正文块建立结构签名，至少覆盖 ul、ol、li、p、标题、blockquote 及实际存在的其他正文块；不凭空要求模型生成源文没有的包装。
- 检查这些结构的数量及层级，禁止整体删除、扁平化为一段文字或破坏列表层级。
- 源文中包含应翻文本的后代正文块，不能被替换为整体空白；保留内容按原有策略核对。
- 仍允许既有规则许可的行内语序调整；不要把所有兄弟元素顺序锁死。
- 初译、Critic 修正、单节点回退统一使用同一个校验出口。
- 新增结构规则应在写回前运行，失败不得先覆盖 DOM 再让覆盖率检查兜底。

这一步检测正文块消失和结构破坏，不声称能够证明每一句译文语义完整。保留结构但句内漏译仍需独立的语义验收。

## 6. 修改四：完成状态与缓存恢复

主要文件：`src/translation/translator.js`、`src/support/cache.js`、`src/support/taskIdentity.js`。

### 6.1 完成判定

- complete：全部计划翻译单元 written，没有未解决写回错误，没有覆盖率缺口，结构校验通过。
- partial：已有真实写回成功，但仍有失败、未处理节点或覆盖率缺口。
- failed：存在应翻单元，但没有真实写回成功，或计划无法安全执行。
- 没有应翻单元的合法保留章节，沿用既有空任务语义，不因本次修复强制失败。

审计标记 selected 只证明“已选”，不能证明 written。覆盖率汇总必须结合源计划和写回结果；即使目标节点已经消失，其未写回状态也必须保留在报告中。

### 6.2 新缓存保存内容

在章节状态中保存计划/写回协议版本、状态摘要、实际 written 数、失败节点及错误码、HTML 摘要，并增加 `requiresSourceRebuild` 标志。不序列化 DOM 引用。

状态摘要保留完整章节计划的节点 ID、源摘要、状态与已写回输出证据。续翻先核对协议版本、源身份和缓存 HTML，再恢复 written 状态、为待补节点重建运行时目标引用。证据不足就从原文重建，不把“当前 DOM 里没有标记”的节点推断为 written。

`totalNodes` 与 `translatedNodes` 使用同一份完整章节计划统计；续翻只发送待补节点，但不能把上一轮已验证成功的节点从章节总数中删掉。如需显示本次补翻量，单独提供 `newlyWrittenNodes`，进度通知不重复累计历史成功。

- 普通 API/格式失败、失败目标与标记仍完整：允许保留已验证部分，并只补失败节点。
- 目标消失、身份异常、父子重叠或状态记录与 DOM 不一致：该章不能走仅补失败节点；下一次从原始章节重建。
- 与原文有关的未覆盖信息继续保存，不能通过删除 DOM 内容让缺口从报告中消失。

### 6.3 旧缓存迁移

1. 修复完整后递增 `TRANSLATION_PIPELINE_VERSION`（当前为 2）；若实施期间已有其他版本变更，继续递增，不写死覆盖。
2. 第一版按现有任务签名机制使旧翻译缓存失效。版本变更范围与现有机制一致，启动日志明确说明原因；若会重建规划等辅助缓存，需在实施说明中如实记录。
3. 不把旧的“complete + 无标记”自动当作符合新写回契约。缺少新协议证据时不能直接赋予新版本身份。
4. 当前版本的正常 partial 缓存仍应只补失败节点；异常缓存按上一节从原文重建。
5. 日志和报告保存异常章节、旧版本、错误节点和恢复方式，便于核对。

不要先手动清空 `.cache_Advances..._zh` 来代替代码修复。真实样本验收使用临时工作副本和独立缓存；正式迁移交给版本机制处理。

## 8. 验收清单

使用真实 `createBatchQueue`、fake provider 和明确译文 fixture 验证调用及写回；不得只使用直接改 DOM 的假队列证明写回正确。

| # | 场景 | 必须断言 |
|---|---|---|
| 1 | li 内只有 p | 只发 p，正文真实替换，complete |
| 2 | strong/em/a/带保留属性 span 包裹引言，再跟 p | 引言和正文都翻；节点不重叠；零漏选 |
| 3 | 外层 li 有引言，内层为 ul/li | 外层只发一次；两段译文都在；内层列表结构保留 |
| 4 | 外层 li 只有内层列表 | 子节点正常翻，父不重复发 |
| 5 | 多个 sibling p、相同文字的两个节点 | 每个源位置独立覆盖，不因文本相同合并任务 |
| 6 | 空白、数字、公式、图片、脚注、链接锚点混合 | 保留规则和保护属性不回退，正文无漏选 |
| 7 | 请求期间目标标记被移除，但原文仍在 | 记录 TARGET_MISSING；不计 written，不得 complete，不反复请求该节点 |
| 8 | 请求期间目标被删除、被替换或同 ID 重复 | 明确结构失败；缺失不被当前 DOM 审计掩盖 |
| 9 | 同批一个目标失败、另一个正常 | 正常目标写回有证据；失败目标被记录；不能整批误报成功 |
| 10 | 重复任务/重复通知 | 有真实成功记录时幂等；无证据不跳过；不重复增加进度 |
| 11 | 模型删除内层 ul/li，或将应翻子块变空 | 写回前拒绝，原结构不被坏响应覆盖 |
| 12 | Critic 删除内层列表 | 与初译共用校验，同样被拒绝 |
| 13 | 旧 partial 缓存有父子失败标记 | 不重复发送重叠任务；从原文重建该章 |
| 14 | 新版本普通 partial → 补失败节点 → complete | 不重复请求已验证成功节点；最终统计和内容正确 |
| 15 | 新版本缓存有结构失败、却没有失败标记 | requiresSourceRebuild 生效，不得零请求跳过 |
| 16 | 旧版本 complete 缓存 | 流程版本迁移使其失效，不能直接复用旧译文 |
| 17 | 字幕/PDF/HTML 基础样本 | 进度、映射、保真和现有结果协议不回退 |

主要扩充 `test_structure_fidelity.mjs`、`test_translation_status.mjs`、`test_content_classifier.mjs` 和必要的错误分类测试。保持现有九组测试入口；无需仅为文件数量再新增测试套件。

执行顺序：相关定向测试 → `npm test` → 临时副本上的真实 EPUB 结构验收。模型译文质量抽查另行执行，不用合成测试结果宣称真实质量已经达标。

## 9. 交付与完成标准

- 代码、测试和缓存版本迁移一并交付，更新设计/架构说明中的状态与完成条件。
- 报告能区分：模型响应失败、格式/结构校验失败、目标写回失败、覆盖率漏选。
- 任一未知目标缺失、未写回节点或正文结构丢失都不能产生 complete。
- 原先的“superseded by an ancestor batch, skipping”无证据成功路径被删除。
- 不把减少报错数量作为正确性证明；以完整内容、结构、真实写回记录和恢复行为为验收依据。
